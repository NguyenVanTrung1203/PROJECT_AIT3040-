# S5-04A — Authoritative synthetic runtime HTTP integration

Date: 2026-11-26. Branch `s5-integration-final`; baseline `8f252c522914aa30ba05bd28368ec60cab71c5a6`.

## Result and architecture

HTTP_RUNTIME_INTEGRATION=PASS_WITHIN_SINGLE_PROCESS_SYNTHETIC_SCOPE. PAUSED_ANCHOR_ACCEPTANCE=PASS. CONTINUOUS_PLAYBACK_ACCEPTANCE=NOT_ACCEPTED: an observed playing evaluation returned 409 when the server clock advanced before publication. TEAM_INTERFACE_APPROVAL=PENDING. REAL_AIS_READINESS=NOT_VERIFIED. Frontend and full G4 end-to-end acceptance are not part of this result.

The app's existing replay routes now use a `ReplayAuthority` backed by the same `ReplayAPI` instance owned by `FixtureProvider`. That one instance registers both the existing S4 source and `s5-01-synthetic-denmark-v1`; the S5 source uses server monotonic time, not a separate frozen fixture clock. The same provider issues current snapshots and candidate objects to M5a, Risk V4 and the alert harness. S4 mock and single-vessel routes remain available. S5 supports **one active fixture session per process**; a second create returns 409. SEEK/RESET replace the S5 session and preserve replay idempotency handling. Multiple simultaneous S5 sessions and multi-worker sharing are not supported.

`RuntimeState` lazily loads one verified M5a service and risk harness per process, with explicit CPU required here, existing integrity checks and bounded concurrency. Missing/invalid config, package or reference makes runtime evaluation unavailable; health, mock and S4 replay remain available. No Forecast Mock fallback is used. App lifespan closes the model service. The S5-01 provider change adds an opt-in backend-clock mode; its original deterministic-clock mode remains available for existing tests.

Session/version/snapshot/anchor and pair are carried in the supplemental transport envelope. The risk payload itself conforms to frozen `risk_response_v1` and contains the forecast; alerts conform to `alert_v1`. No frozen contract file was changed. Final provider/session validation and alert commit occur under provider lock, and the HTTP route rechecks before returning. Because the replay clock or session may change after that lock is released while bytes are serialized or in transit, this is a **server-side linearization guarantee**, not a guarantee of freshness on network receipt. Frontend must reject any response whose binding no longer matches its latest session/version/snapshot/anchor. Replay lock is not held through inference or network delivery.

## HTTP interface for frontend

All supplemental `/api/v1/runtime/...` responses are fixture-only transport DTOs, not changes to the frozen V1 schemas. Existing `/health`, `/api/v1/mock/tracks` and `/api/v1/replay/sessions` routes remain.

| Method and endpoint | Request | Response / frontend use | Errors and binding |
|---|---|---|---|
| `POST /api/v1/replay/sessions` | `{"source_id":"s5-01-synthetic-denmark-v1","start_time":"2024-11-01T00:09:00Z"}` | Existing Replay V1 session; create the synthetic source. Use SEEK with idempotency key to obtain PAUSED at a chosen anchor. | Existing replay errors; 409 if another S5 session is active. Session is authoritative. |
| `GET /api/v1/replay/sessions/{session_id}/tracks` | Optional existing `limit`, `offset`, `snapshot_id` | Existing Replay V1 tracks; pass the candidate snapshot ID to read the same pin. | Existing replay errors; old replaced S5 session returns 409. |
| `POST /api/v1/replay/sessions/{session_id}/control` | Existing Replay V1 `action`, `expected_version`, optional `target_time`; `Idempotency-Key` for SEEK/RESET | PLAY/PAUSE and session replacement on SEEK/RESET. | Existing replay errors. Immediately invalidate old client forecast/risk/alert on any control or session/clock change. |
| `GET /api/v1/runtime/status` | None | Supplemental `source_id`, scope, runtime status/reason, load count, official-alert and team-review status. `NOT_INITIALIZED` indicates lazy loading has not yet been attempted. | Missing config/package does not crash health or replay; evaluation returns 503. |
| `GET /api/v1/runtime/sessions/{session_id}/candidates` | Current S5 session | Supplemental envelope: `session_id`, `session_version`, `snapshot_id`, `anchor_utc`, `expected`, `evaluated`, `eligible`, `unavailable`, and `pairs` with pair IDs, vessel IDs and reasons. Use this for selection and coverage. | 404 invalid/non-S5 source; 409 replaced session; 503 resource/snapshot failure. No silent distance filtering. |
| `POST /api/v1/runtime/sessions/{session_id}/evaluate` | `{"snapshot_id":"<snapshot UUID>","pair_id":"<pair:v1 ID>","request_id":"<idempotency ID>"}` | Supplemental binding envelope with `risk` conforming to `risk_response_v1`; embedded V1 forecast and risk are from the same evaluation. Unavailable pair returns null decision/score. | 404 unknown pair; 409 stale snapshot/session, conflicting identity, or stale completion; 503 unavailable runtime. Arbitrary scores/tensors/thresholds/trust flags are forbidden. |
| `GET /api/v1/runtime/sessions/{session_id}/alerts?snapshot_id=...` | Current session and snapshot | Supplemental binding envelope with `items` (`alert_v1`) and `total`. | 409 stale snapshot/session; 503 unavailable runtime. DATA_UNAVAILABLE is not RESOLVED. |

Example status before first evaluation: `{"source_id":"s5-01-synthetic-denmark-v1","scope":"SYNTHETIC_FIXTURE","runtime_status":"UNAVAILABLE","reason":"NOT_INITIALIZED","model_load_count":0,"official_alerts":false,"team_interface_approval":"PENDING"}`. An evaluation response has the shape `{"session_id":"<UUID>","session_version":0,"snapshot_id":"<UUID>","anchor_utc":"2024-11-01T00:09:00Z","risk":{...}}`; `risk` is the complete frozen schema object, not the abbreviated example shown here. The candidate response supplies the snapshot/pair IDs. Frontend should display loading while a request is pending, unavailable/null distinctly from false, and errors explicitly; never convert a 409 or missing result into no alert.

## Evidence and limitations

Actual-model tests used HTTPX ASGI transport against FastAPI routes with the locked checkpoint/scalers and V4. At PAUSED 00:09, 10 pair evaluations produced 1 alert, 5 no-alert and 4 unavailable in 15.54 s total. At PAUSED 00:15, 10 produced 1 alert and 9 no-alert in 30.44 s total. AB risk matched the earlier S5-03 evidence to 1e-6: 0.8832455466 and 0.9638132257 respectively. Forecast/risk shared one V1 response and horizon; direct numeric comparison of every HTTP forecast to stored historical predictions was not performed because S5-02 did not record fixture forecast arrays. Repeated and concurrent retries produced one alert. These times include HTTP, integrity and risk work; they are observations, not an SLA.

One continuous PLAY measurement took 0.678 s and returned 409 while the server clock moved from 00:09:00 to 00:09:01. The clock was not frozen and stale results were not returned in that test. Latency varies and this single observation does not establish sustainable live throughput. Client-side binding checks, throughput and a suitable continuous-playback policy remain open.

The final combined Q1-guarded run outside the Windows sandbox passed **45 tests in 79.07 s**: six S5-04A HTTP test nodes, 22 S4 replay/mock backend nodes and 17 S5-01 regression nodes. One Starlette TestClient/httpx deprecation warning was emitted. An additional S4 facade control/invalid-authority/shutdown test passed separately in 9.36 s. Both runs recorded `hash_opens=0`, `blocked_deserialization=0`, `blocked_other_opens=0`. The initial sandbox HTTP attempt hung on the previously recorded Windows socket/thread issue; the permitted outside-sandbox execution succeeded. Earlier test runs exposed and fixed test fixture restoration and APIProblem error mapping before the final runs.

Tests cover schema mapping, load-once, missing config, invalid authority, S4 facade controls and mock/health, paused coverage, historical AB risk, duplicate/concurrent retry, session replacement, stale snapshot, and deterministic SEEK/RESET races during inference. No full project regression, CUDA, training, calibration or T15 benchmark was run. User data, Model Lock, Risk V4, thresholds and Contract V1 are unchanged. No frontend, commit, push or merge.
